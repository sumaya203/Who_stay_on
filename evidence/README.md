# Evidence

Reproducible artifacts behind the verification claims in the project README.
Everything here is generated by the engine in `src/lib` — nothing is hand-written.

| File | What it is |
| --- | --- |
| `sample_output.json` | The response for `public/sample_input.json`: `value_total = 200`, `fuel_total_litres = 25`, five outage slots `slot_1, slot_2, slot_4, slot_5, slot_8`, nothing shed. |
| `regression_input.json` / `regression_output.json` | The same run pinned as a regression fixture. |
| `boundary_input.json` / `boundary_output.json` | The same day with the fuel budget cut from 50 L to 15 L. The schedule stays feasible and optimal (`value_total = 150`, `fuel_total_litres = 14.3`): `B_NORMAL` is dark twice and `C_NORMAL` four times, each with a generated explanation. This is the case that used to end in a false `infeasible`. |
| `feasibility_probe.mjs` | Independent feasibility search for the 12-shop / all-outage / 40 L instance that the old solver wrongly reported as `infeasible`. Run with `node evidence/feasibility_probe.mjs`; it prints `feasible: true` together with a witness schedule. |
| `solver_crosscheck.mjs` | Randomised cross-check of the production solver against the independent reference oracle (`tests/helpers/reference.js`). `node evidence/solver_crosscheck.mjs 500` reports 238 mutually feasible seeds, 0 hard mismatches and 5 fuel tie-break differences; exits non-zero on any status, value or constraint mismatch. |
| `live_api_checks.mjs` | 35 live HTTP checks (boundaries, rejections, infeasible cases, wrong method) against a running server. Run with `node evidence/live_api_checks.mjs` while the app is up; exits non-zero on the first broken expectation. |

## Regenerating

```bash
node test_script.js                 # rewrites the four *.json fixtures
node evidence/feasibility_probe.mjs # witness for the 40 L instance
npx vitest run                      # 153 automated tests
node evidence/solver_crosscheck.mjs 500  # solver vs independent oracle
node evidence/live_api_checks.mjs   # needs `npm run dev` or `npm start` in another shell
```
